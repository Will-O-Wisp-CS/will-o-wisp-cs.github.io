# 公認CSサポート 自動申請 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions の Run workflow 画面で6枠（A①〜C②）に会場と日付を入れると、dmp-ranking.com の店舗管理画面で「公認CSサポート○月開催申請」を申請まで済ませる。

**Architecture:** `src/apply/` に純粋関数（入力の検証・入力値の計算・画面 HTML の読み取り・枠の割り当て・状態表）を置いて vitest でテストする。Node 専用の入口 `apply.ts` が Playwright で画面を操作し、`.github/workflows/apply.yml`（`workflow_dispatch`）から実行する。ログイン情報は Secrets。

**Tech Stack:** TypeScript（Node 22 の型除去で直接実行）、Playwright（chromium）、vitest、GitHub Actions

**Spec:** `docs/superpowers/specs/2026-11-17-dmp-apply-design.md`

## Global Constraints
- テスト名・コメント・ログ・状態表は日本語。コミットメッセージは `feat:` / `test:` / `chore:` 付きの英語
- 入力は `normalize('NFKC')` してから解釈する（全角数字・全角スラッシュ可）
- `apply.ts` から import されるファイルの import は `.ts` 拡張子付き（`src/schedule/fetch.ts` と同じ）
- 機能フォルダ同士は import しない（`src/schedule/csv.ts` の `parseMonth` は使わず `src/apply/` に持つ）。ルート直下にファイルを増やさない。`index.html` は作らず、`vite.config.ts`・メニュー・トップには載せない
- パスワード・`DMP_CONTACT_MAIL` をログ・状態表・リポジトリに出さない。スクリーンショットは `mail` 欄を `mask` する。artifact は `retention-days: 1`
- 対象は大会名がちょうど `公認CSサポートYYYY年M月開催申請` の行だけ（【リモートデュエマ】・ファンイベント・全国大会は対象外）
- 日時: 参加表明・デッキ提出の開始＝開催日14日前 20:00、参加表明締切＝開催日の受付開始10分前、デッキ提出締切＝開催日 23:59
- 「確認だけ」（`dry_run`、既定 true）では〔更新保存〕も〔上記内容で申請する〕も押さない

## Review Focus
- 同じアカウントで2枠を指定し、その月の1枠がすでに埋まっている → そのアカウントの指定はすべて飛ばし、理由を出す（Task 4 のテスト）
- 開催日が月初（2027-01-03）で、参加表明の開始が前の月（2026/12/20）になる（Task 2 のテスト）
- 全角の日付・月（`１／１０`、`２０２７−０１`）（Task 1 のテスト）
- パスワード違い・ログイン切れで、ログイン画面に戻される → そのアカウントだけ失敗にして、ほかのアカウントは続ける（Task 3 の `isLoginPage` のテストと Task 5 の分岐）
- 入力で2つの枠に同じ日付・同じ会場を入れた → 入力エラーにして、どの枠も申請しない（Task 1 のテスト）

### Task 5: Playwright の入口とワークフロー（`apply.ts`・`apply.yml`）

**Files:**
- Create: `src/apply/apply.ts`, `.github/workflows/apply.yml`, `src/apply/workflow.test.ts`
- Modify: `package.json`（scripts `"apply": "node src/apply/apply.ts"`、devDependencies `playwright`）、`.gitignore`（`src/apply/out/`）、`.claude/CLAUDE.md`（フォルダ構成に `apply/`、ドメインルールに「自動申請」の節を設計書の要点で足す）

**Interfaces:**
- Consumes: Task 1〜4 のすべて
- 環境変数: workflow の入力を `INPUT_MONTH` / `INPUT_A1_VENUE` … / `INPUT_DRY_RUN` で渡し、`parseApplyInput` 用にキーを小文字・`INPUT_` 抜きに戻す。Secrets は `DMP_A_ID` / `DMP_A_PASSWORD` / … / `DMP_CONTACT_MAIL`

`apply.ts` の流れ（設計書「処理の流れ」と「実装側で決めたこと」のとおり）:
1. `parseApplyInput` → 失敗ならメッセージを出して exit 1（ログインしない）
2. 対象アカウント（指定のあるアカウント。全部空欄なら A・B・C のうち Secrets のあるもの）ごとに新しい `browser.newContext()`。指定があるのに Secrets が無いアカウントは失敗にする
3. `https://www.dmp-ranking.com/shop/` で `LoginID` / `Password` を入れて「ログイン」→ `shopmenu.asp` へ。`isLoginPage` なら「ログインできませんでした」で失敗、次のアカウントへ
4. `findMonthRow` → `shopevent.asp?EventID=…` → `parseMonthPage` → `planAccount`
5. `apply` ごとに `shopeventsub.asp?EventID=…&Seq=…` を開き、`texts` は `fill`、`selects` は `selectOption`、`hidden`（`Lat` / `Lng`）は `evaluate` で設定、ジャッジは `JudgeMoto` で選んで `JudgeAdd()`。`out/` に `{slot}-filled.png`（`mask: [page.locator('[name=Mail]')]`, `fullPage: true`）
6. `dryRun` ならここで次へ（保存しない）。そうでなければ〔更新保存〕→ 月の申請画面で日付が登録されたことを確認。アカウントの全件が保存できたら〔上記内容で申請する〕→ 管理メニューで `申請確認中です` を確認し `{account}-applied.png`
7. `page.on('dialog')`: `dryRun` では常に `dismiss`。本番では `上記内容で申請してよろしいですか` / 更新保存の確認だけ `accept`、それ以外は `dismiss` して失敗にする
8. `summaryMarkdown` をログと `GITHUB_STEP_SUMMARY`（あれば）に書く。失敗が1つでもあれば exit 1
- ログにパスワード・メールアドレスを出さない。例外のメッセージを出すときも `DMP_CONTACT_MAIL` の値を `***` に置き換える

`apply.yml`:
- `name: 大会を申請`、`on: workflow_dispatch`、入力は設計書の表どおり（`month` 必須、`*_venue` は `type: choice` で `options: ['', 竜星の嵐新宿店, 晴れる屋3]`、`*_date` は string、`dry_run` は boolean 既定 true）。各入力の `description` は `A① 会場` / `A① 日付（10 / 1/10 / 2027-01-10）` など
- `concurrency: { group: apply, cancel-in-progress: false }`、`permissions: contents: read`
- steps: checkout → setup-node 22（npm キャッシュ）→ `npm ci` → `npx playwright install --with-deps chromium` → `npm run apply`（env に入力と Secrets）→ `actions/upload-artifact@v4`（`if: always()`、`path: src/apply/out/`、`retention-days: 1`、`if-no-files-found: ignore`）
