# 鬼火CS 帳簿（青色申告）ページ 設計書

- 作成日: 2026-10-07
- 状態: レビュー待ち

## Context
鬼火CSの主催者として、**青色申告（65万円控除）**のための帳簿を**無料で**つけたい。
会計ソフトは使わず自作する（月額費用を払いたくないため）。

- 収入は鬼火CSの開催ごとの参加費（会場で現金で受け取る）だけ
- 経費は開催と関係ないものもある。主なものは店舗に払う会場費・賞品代・交通費・飲食の接待交際費
- 減価償却が必要な 10万円以上の備品は今のところない。消費税は免税事業者の前提
- 領収書のデータも保存したい
- 開催があったら（中止でない限り）記録が必要なので、記録漏れをリマインドしたい
- スマホがメイン。PC でも同じデータを見る
- **本人以外には見えないこと**

決算書（損益計算書・貸借対照表）は国税庁「確定申告書等作成コーナー」に手入力し、e-Tax で提出する。
このページの役割は**複式の帳簿をつけ、作成コーナーに入力する数字を出す**ところまで。

## 方針
- 同じサイトに `/tax/` ページを追加する。メニュー・トップページのカードには載せない。`<meta name="robots" content="noindex">` を付ける
- データは**本人の Google ドライブ**に保存する（帳簿は JSON、領収書は画像・PDF）。リポジトリには一切入れない
- 本人以外は見られないことを、Google ログインで担保する
  - OAuth 同意画面は「テスト」状態のままにし、テストユーザーに本人のアカウントだけを登録する。他のアカウントはログインできない
  - 仮に他人がログインできても、見えるのはその人自身のドライブだけ
  - ページ内で ID・パスワードを照合する方式は使わない（静的サイトでは正解がコードから読めるため）
- ログインしていない間は、売上・経費・リマインドを含めて何も表示しない
- 簿記を意識せずに「取引」を入力し、裏で仕訳（借方・貸方）を作る。1取引＝1仕訳（借方1つ・貸方1つ）とし、複合仕訳は扱わない
- 金額はすべて整数（円）
- 会計期間は暦年（1/1〜12/31）

## 勘定科目
`src/tax/accounts.ts` に固定の一覧として持つ。決算書の科目名をそのまま使う。

| 区分 | 科目 |
|---|---|
| 資産 | 現金 / 普通預金 / 事業主貸 |
| 負債・資本 | 事業主借 / 元入金 |
| 収益 | 売上高 |
| 経費 | 地代家賃 / 広告宣伝費 / 旅費交通費 / 接待交際費 / 消耗品費 / 通信費 / 支払手数料 / 外注工賃 / 雑費 |

- 会場費は地代家賃、賞品代は広告宣伝費、外注費（ジャッジ・スタッフへの報酬など）は外注工賃（2026-10-08 追加）。毎年同じ科目で処理する
- 経費の入力画面では、経費科目の横に用途の例を出す（例: 広告宣伝費「賞品代など」）
- 経費科目の表示順は設定で変えられる。科目そのものの追加はしない

## 取引の入力
| 種類 | 入力項目 | 仕訳 |
|---|---|---|
| 売上 | 開催、参加人数、参加費、金額 | 現金 / 売上高 |
| 経費 | 開催（任意。選ぶと日付に開催日が入る）、日付、科目、金額、支払方法、取引先、メモ、領収書 | 経費科目 / 支払方法 |
| 振替 | 日付、金額、移動元、移動先、メモ | 移動先 / 移動元 |

- **支払方法**: 現金 / 普通預金 / 個人のお金 / クレカ / PayPay / 交通系IC（2026-10-08 追加）。クレカ・PayPay・交通系IC はプライベートと共用なので個人のお金と同じく事業主借で記帳し、どれで払ったかを取引の `payment` に残す。摘要に「（クレカ）」などを付け、一覧で支払方法で絞り込める
- **振替の例**: 事業用の現金を生活費に回す（事業主貸 / 現金）、個人のお金を事業用の現金に入れる（現金 / 事業主借）、預け入れ（普通預金 / 現金）
- **売上**: 金額の初期値は「参加人数 × 参加費」。割引・返金に対応するため金額は手で直せる。参加費の初期値は設定値（前回入力した値で更新する）。日付は開催日
- 1つの開催に売上を複数件入れてもよい（追加の受け取りなど）
- **旅費交通費**（2026-10-08 追加）: 科目で旅費交通費を選ぶと支払方法の初期値は交通系IC。設定で登録したテンプレ（区間・片道運賃。例: 笹塚⇔新宿 140円）を選ぶと金額に運賃、メモに区間が入る。片道 / 往復のラジオ（新規入力のみ）で往復にすると同じ内容の取引を2件保存する（領収書は1件目にだけ付ける）
- 取引は一覧から編集・削除できる。削除するとその取引の領収書ファイルはドライブのゴミ箱に移す

## 開催との連動とリマインド
- ビルド時に `src/shared/events.json` を import し、ページを開いたときに帳簿にない開催を帳簿の `events` に追加する
  - 開催の ID は大会詳細ページの URL（`ScheduleEvent.url`）
  - `events.json` は当月1日以降しか持たないので、過去月の開催は帳簿側にだけ残る。`events.json` から消えたことを中止とはみなさない
- **開催の状態**
  - 未記録: 開始時刻（JST）を過ぎていて、売上がまだなく、中止でもない
  - 記録済み: その開催にひも付いた売上が1件以上ある
  - 中止: 本人が「中止」を押したもの。取り消せる
  - これから: 開始時刻前
- 設定の**記帳開始日**より前の開催はリマインドしない（使い始める前の開催で埋まらないように）
- ホーム画面の一番上に「未記録の開催が N 件あります」と出し、各開催に「売上を入力」「中止にする」ボタンを付ける
- 開催ごとの収支（売上 − その開催にひも付けた経費）を一覧で見られる

## 領収書
- **紙の領収書**: 紙の原本を7年保管する運用とし、アプリの画像は控えとする。スキャナ保存の要件は満たさない（ページの注意書きにその旨を書く）
- **データの領収書（PDF・メール等）**: 電子取引データとしてドライブに保存する。売上5,000万円以下の検索要件の緩和を使い、次の形で保存する
  - ファイル名は `YYYY-MM-DD_金額_取引先.拡張子`（例: `2026-10-04_5500_晴れる屋.pdf`）。取引の日付・金額・取引先を変えたらファイル名も変える
  - 帳簿の一覧で日付・金額・取引先から検索できる
  - 改ざん防止は国税庁ひな形の事務処理規程で行う（規程はアプリの外で本人が用意する。ページの注意書きに書く）
- 領収書は `<input type="file" accept="image/*,application/pdf" multiple>` で追加する。`capture` は付けない（スマホで「カメラで撮影」と「ファイルを選択」の両方を選べるようにするため）
- 画像は長辺 2000px・JPEG に縮小してからアップロードする。PDF はそのまま
- 1つの取引に複数のファイルを付けられる

## Google ドライブ
- ログインは Google Identity Services のトークンモデル（`https://accounts.google.com/gsi/client`）。スコープは `https://www.googleapis.com/auth/drive.file` のみ（アプリが作ったファイルだけを扱える。審査不要）
- アクセストークンは約1時間で切れる。切れたら API 呼び出しの前に取り直す（同意済みなら画面は出ない）。トークンは保存せずメモリに置く
- フォルダ構成（本人のマイドライブに見える形で作る）

```
鬼火CS帳簿/
  settings.json          設定
  ledger-2026.json       その年の帳簿
  backup/                帳簿の直前版（開いて最初の保存とその後1時間ごと。年ごとに最新30件まで）
  receipts/2026/         その年の領収書
```

- 保存時の衝突防止: 帳簿・設定の JSON の `rev`（保存ごとに +1）を読み込んだときに覚えておき、保存前にドライブ上の中身を読み直して違っていたら保存せず「他の端末で更新されています。再読み込みしてください」と出す（2026-10-08: ドライブのファイルの version は作成直後などに勝手に増えるため使わない）
- 速さ（2026-10-08）: バックアップは開いて最初の保存とその後1時間ごとだけ。領収書は同時にアップロード。使うフォルダはログイン後に先読み
- 通信に失敗したら「保存できませんでした」と出し、入力内容は画面に残す。オフラインでの保存・後から同期はしない
- クライアント ID は `src/tax/config.ts` に書く（秘密の値ではない）

## データ形式

```ts
type AccountId = 'cash' | 'bank' | 'ownerDraw' | 'ownerLoan' | 'capital' | 'sales'
  | 'rent' | 'advertising' | 'travel' | 'entertainment' | 'supplies'
  | 'communication' | 'fees' | 'misc';

type Receipt = { fileId: string; name: string; mimeType: string };

type Transaction = {
  id: string;            // crypto.randomUUID()
  kind: 'sale' | 'expense' | 'transfer';
  date: string;          // 'YYYY-MM-DD'
  amount: number;        // 円（正の整数）
  debit: AccountId;
  credit: AccountId;
  eventId?: string;      // 売上は必須、経費は任意
  participants?: number; // 売上のみ
  fee?: number;          // 売上のみ
  counterparty?: string;
  memo?: string;
  receipts: Receipt[];
  updatedAt: string;     // ISO
};

type LedgerEvent = { id: string; date: string; venue: string; start: string; cancelled: boolean };

type Ledger = {
  year: number;
  opening: { cash: number; bank: number }; // 期首残高。元入金 = cash + bank
  events: LedgerEvent[];   // 開催日がその年の開催だけ
  transactions: Transaction[];
};

type Settings = {
  startDate: string;        // 記帳開始日
  defaultFee: number;       // 参加費の初期値
  expenseOrder: AccountId[];
};
```

- 新しい年の帳簿を初めて開いたとき、前年の帳簿があれば期末の現金・普通預金を `opening` に入れて作る。前年がなければ期首残高の入力を求める
- 事業主貸・事業主借は年をまたいで繰り越さない（翌年の元入金に含まれる）

## 決算
作成コーナーの入力欄と同じ並びで出す。

- **損益計算書**: 月別の売上高、経費の科目別合計、青色申告特別控除前の所得金額
- **貸借対照表**: 期首・期末の 現金 / 普通預金 / 事業主貸 / 事業主借 / 元入金、期末の「青色申告特別控除前の所得金額」
  - 期末の元入金は期首と同じ（翌年の元入金 = 期首元入金 + 所得 + 事業主借 − 事業主貸）
- **仕訳帳・総勘定元帳**: 画面で見られ、CSV で書き出せる（BOM 付き UTF-8・CRLF。既存の月別 CSV と同じ）
  - 仕訳帳: 日付, 借方科目, 貸方科目, 金額, 摘要
  - 総勘定元帳: 科目ごとに 日付, 相手科目, 摘要, 借方金額, 貸方金額, 残高
  - 摘要は「取引先 メモ」、売上は「鬼火CS in ○○ N人」

## 画面
1ページ内のタブ切り替え。スマホ幅を基準にする。

1. **ホーム**: 未記録の開催、今年の売上・経費・所得
2. **入力**: 売上 / 経費 / 振替。経費は「領収書を追加」ボタンを大きく出す
3. **一覧**: 取引の一覧。日付範囲・金額・取引先・科目で絞り込み。開催ごとの収支もここ
4. **決算**: 年を選んで損益計算書・貸借対照表、CSV 書き出し
5. **設定**: 記帳開始日、参加費の初期値、経費科目の並び、期首残高、ログアウト

未ログイン時は「Google でログイン」ボタンと、注意書き（紙の領収書の保管・事務処理規程）だけを出す。

## 構成
- `src/tax/index.html` — ページ（`vite.config.ts` の input に追加。メニュー・トップには載せない）
- `src/tax/main.ts` — DOM。ログイン状態の切り替え、タブ、各フォーム
- `src/tax/accounts.ts` — 勘定科目の一覧と表示名
- `src/tax/journal.ts` — 入力値 → `Transaction` の変換と検証（`ParseResult` で返す）
- `src/tax/reminder.ts` — 帳簿への開催の取り込み、開催の状態判定
- `src/tax/report.ts` — 損益計算書・貸借対照表・総勘定元帳の集計、翌年の期首残高
- `src/tax/csv.ts` — 仕訳帳・総勘定元帳の CSV
- `src/tax/receipt.ts` — 領収書のファイル名、画像の縮小
- `src/tax/drive.ts` — Google ログインとドライブの読み書き（フォルダ作成、JSON の読み書き、アップロード、名前変更、ゴミ箱、version 比較）
- `src/tax/config.ts` — OAuth クライアント ID

`main.ts` と `drive.ts` 以外は純粋関数にして vitest でテストする（`receipt.ts` の画像縮小は除く）。

## Google Cloud の設定（本人が1回だけ行う）
1. Google Cloud Console でプロジェクトを作る
2. 「Google Drive API」を有効にする
3. OAuth 同意画面: ユーザーの種類「外部」、公開ステータス「テスト」のまま、テストユーザーに本人の Gmail だけを追加、スコープに `drive.file`
4. 認証情報 → OAuth クライアント ID（ウェブアプリケーション）。承認済みの JavaScript 生成元に `https://will-o-wisp-cs.github.io` と `http://localhost:5173`
5. 発行されたクライアント ID を `src/tax/config.ts` に書く
