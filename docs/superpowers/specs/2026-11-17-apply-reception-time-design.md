# 自動申請: 受付開始時刻の指定 設計書（小さな変更）

- 作成日: 2026-11-17
- 状態: 承認済み
- 元の設計書: 2026-11-17-dmp-apply-design.md

## 目的
受付・開始の時刻は会場ごとに `venues.json` で決まっているが、開催によって時刻を変えたいことがある。
枠ごとに受付開始時刻を入れられるようにし、空欄なら会場の時刻で申請する。

## ゴール / ゴールでないもの
- ゴール: 6枠（A①〜C②）それぞれに「受付開始」の入力を足す。入れた枠だけ時刻を変えて申請する
- ゴールでないもの: 開始時刻・締切を個別に指定すること（受付から決める）。`venues.json` の時刻を変えること
- 失敗とみなすこと: 受付だけ変わって、開始・締切・タイムスケジュールの文面が元の時刻のまま申請される

## 方式（Approaches）
1. **全部まとめてずらす（採用。主催者が選択）** — 受付開始を入れると、元の受付との差（分）だけ、開始時刻とタイムスケジュールの文面の時刻をすべてずらす。参加表明締切は受付の10分前のまま
2. 受付・開始・締切だけずらす — 文面の時刻が食い違い、手で直す必要があるので不採用

## 決めたこと
- 入力: `a1_reception` 〜 `c2_reception`（string、空欄可）。入力は全部で20個（上限25個以内）
- 書き方: `10:40` / `1040` / `10時40分` / `9:05`（全角可）。分は 00〜59
- 誤りとして止めるもの（他の誤りと同じく、1つでもあればどの枠も申請しない）
  - 会場・日付のない枠に受付開始だけ入っている
  - 書き方が違う・存在しない時刻
  - ずらした結果、受付締切（受付の10分前）や文面の時刻が日をまたぐ（0:00 より前・24:00 以降）
- ずらし方: 開始＝元の開始＋差、締切＝新しい受付−10分。タイムスケジュールの文面 `schedule` の中の `H:MM` / `HH:MM` をすべて差の分だけずらし、元と同じ桁の書き方で戻す（`10:10` → `10:40`）
- ログの「保存しました」の行と状態表は今のまま（受付時刻は出さない） — **こちらの判断**
- 計算は `fields.ts`（`buildFields` に受付開始を渡す）と `input.ts`（入力の解釈）に入れ、テストを足す。`workflow.test.ts` の入力数を 20 に直す
- CLAUDE.md と元の設計書の「使い方」に受付開始の入力を書き足す
