# 鬼火CS 帳簿「ジャッジ」タブ 設計書

- 作成日: 2026-11-03
- 状態: レビュー待ち

## Context
鬼火CSの各開催に、誰が HJ（ヘッドジャッジ）・FJ（フロアジャッジ）に入るかを Google スプレッドシートで管理している。
列は 開催日 / 曜日 / 受付開始時刻 / 会場名 / HJ / FJ / FJ で、大会の情報は手で書き写している。

- 大会の情報（開催日・受付開始時刻・会場）は自動で取り込みたい
- HJ・FJ はプルダウンから選ぶか、手入力する
- **本人以外には見えないこと**

## 方針
- 帳簿（`/tax/`）に「ジャッジ」タブを足す。帳簿の Google ログイン・ドライブ保存をそのまま使うので、見られるのは本人だけ。メニュー・トップページのカードには載せない
- 大会は帳簿と同じく `events-archive.json` と `events.json` を `mergeEventLists` で合わせた一覧（`main.ts` の `schedule`）から作る。毎日の自動取得で新しい大会が増える
- 割り当ては帳簿本体とは別のファイル `judges.json` に保存する。帳簿の `rev`・バックアップには関わらない

## 画面

### 表
列はスプレッドシートと同じ。

| 列 | 中身 |
|---|---|
| 開催日 | `26/11/03` の形 |
| 曜日 | `火` など。マーカーの色は `/schedule/` と同じ（土＝青 / 日＝赤 / 祝日＝黄 / 平日＝なし、祝日優先） |
| 受付開始時刻 | 開始の20分前（`10:30` 開始 → `10:10`） |
| 会場名 | 開催地（大会名「鬼火CS in ○○」の ○○）。設定で決めた会場の色の札で表示する |
| HJ | 1枠 |
| FJ | 最初は1枠。「＋」で大会ごとに増やせる |

- 月ごとに見出し（`2026年11月`）で区切り、開催日・開始時刻の順に並べる
- 表示するのは JST の今月以降の開催。「過去の開催を表示」を押すと前の月も出す
- 開いている年の帳簿でその開催が中止になっていれば、行を薄くして「中止」と出す（割り当ての入力はできる）
- スマホでは横にスクロールする表にする（開催日・曜日の列は固定しない。YAGNI）

### HJ・FJ の入力
- 各枠は `<input list="judge-names">` の入力欄。候補は設定の `judgeNames`（登録した順）
- 候補から選んでも、そのまま手入力してもよい。手入力した名前は候補に足さない
- 入力は前後の空白を取る（`trim`）。全角・半角は変えない（名前なので `NFKC` はかけない）
- 欄からフォーカスが外れ（`change`）、値が変わっていたら保存する
- FJ の「＋」は空の枠を1つ足すだけで、保存はしない。保存のとき空の FJ 枠は詰める
- HJ が空で FJ もない開催は `judges.json` から消す

### 設定タブ
- **ジャッジの名前**：名前の一覧。追加・削除・上下の並べ替え。重複は足さない
- **会場の色**：大会一覧に出てくる会場（重複なし、名前順）ごとに、決まった色（8色程度、`tax.css` の変数）から選ぶ。選んでいない会場はグレー

## データ

### `judges.json`（ドライブの「鬼火CS帳簿」フォルダ）
```ts
type JudgeAssignment = { hj: string; fj: string[] };
type Judges = {
  /** 開催 ID（大会詳細ページの URL）→ 割り当て */
  assignments: Record<string, JudgeAssignment>;
  /** 保存のたびに1増やす（Ledger.rev と同じ） */
  rev?: number;
};
```
- ファイルがなければ空（`{ assignments: {} }`）として扱い、最初の保存で作る
- 保存前にドライブ上の `rev` と比べ、違えば保存せず「他の端末で更新されています」と出して読み直す（帳簿と同じ）
- 年をまたいでも1ファイル。過去の割り当ても消さない
- 大会一覧から消えた開催の割り当ては、表には出さないがファイルには残す
- バックアップは取らない（帳簿ほど重くない。必要になったら足す）

### `settings.json` に足す項目
```ts
/** ジャッジの名前（プルダウンの候補の並び。追加前の設定にはない） */
judgeNames?: string[];
/** 会場 → 色の名前（追加前の設定にはない） */
venueColors?: Record<string, VenueColor>;
```
`VenueColor` は `'red' | 'orange' | 'yellow' | 'green' | 'teal' | 'blue' | 'purple' | 'pink'`。

## コード

| ファイル | 役割 |
|---|---|
| `src/tax/judges.ts` | 純粋関数：表の行を作る（受付開始時刻・曜日・月ごとの区切り・表示する範囲）、割り当ての更新（trim・空の FJ を詰める・空なら消す）、会場の一覧、名前の追加・並べ替え |
| `src/tax/judges.test.ts` | 上のテスト |
| `src/tax/view-judges.ts` | ジャッジタブの画面 |
| `src/tax/view-settings.ts` | 名前と会場の色の欄を足す |
| `src/tax/store.ts` | `loadJudges` / `saveJudges`（`rev` の比較は既存の仕組みに合わせる） |
| `src/tax/main.ts` | タブの追加。ログイン後に `judges.json` も読む |
| `src/tax/ledger.ts` | `Settings` に項目を足す。`Judges` 型・`VenueColor` 型 |
| `src/tax/tax.css` | 会場の色・曜日のマーカー |
| `src/shared/calendar.ts` | `src/schedule/calendar.ts` を移す（帳簿からも祝日判定を使うため。機能フォルダ同士は import しない決まり）。`schedule/` の import を直す |

- 保存中は `busy.ts` のスピナー（「保存しています…」）を出す。ジャッジの保存では「保存しました」の表示とページ上部へのスクロールはしない（1枠ずつ保存するので邪魔になる）
- 保存の順番は既存の `queue.ts` に並べ、続けて入力しても順に保存する
- 保存に失敗したら、入力欄の値を保存前に戻してエラーを出す

## テスト
- 受付開始時刻：`10:30` → `10:10`、`17:10` → `16:50`（時をまたぐ）
- 月ごとの区切りと並び順、今月以降だけ／過去も含めた表示
- 割り当ての更新：trim、空の FJ を詰める、HJ・FJ が空なら消す
- 会場の一覧：重複なし・名前順
- 名前の追加（重複しない）・削除・並べ替え
- `calendar.ts` は移すだけ。既存のテストも `shared/` に移す
